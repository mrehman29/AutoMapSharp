# AutoMapSharp 1.0.0

The first General Availability (GA) release of AutoMapSharp: a free, MIT-licensed object mapper for .NET with an API that will feel familiar if you have used AutoMapper.

AutoMapSharp 1.0.0 follows Semantic Versioning 2.0. The public API surface is frozen and guaranteed backwards-compatible (binary and source) across all 1.x releases, tracked via `PublicAPI.Shipped.txt` and `AnalyzerReleases.Shipped.md`.

## Packages

| Package | What it is for |
|---|---|
| [AutoMapSharp](https://www.nuget.org/packages/AutoMapSharp) | The core mapping engine, with the source generator and analyzers built in |
| [AutoMapSharp.Extensions.DependencyInjection](https://www.nuget.org/packages/AutoMapSharp.Extensions.DependencyInjection) | `AddAutoMapSharp` for `IServiceCollection` |
| [AutoMapSharp.Collections](https://www.nuget.org/packages/AutoMapSharp.Collections) | Merge collections by key, a replacement for AutoMapper.Collection |
| [AutoMapSharp.MigrationAnalyzer](https://www.nuget.org/packages/AutoMapSharp.MigrationAnalyzer) | IDE quick fixes that rewrite AutoMapper code |
| [dotnet-automapsharp-migrate](https://www.nuget.org/packages/dotnet-automapsharp-migrate) | A .NET tool that migrates a whole folder from AutoMapper |

```bash
dotnet add package AutoMapSharp
dotnet add package AutoMapSharp.Extensions.DependencyInjection
dotnet add package AutoMapSharp.Collections
dotnet add package AutoMapSharp.MigrationAnalyzer
dotnet tool install --global dotnet-automapsharp-migrate
```

Targets .NET Standard 2.0, .NET 8 and .NET 9.

## Highlights

- **Familiar API.** Mapping modules, `DefineMap`, `ForProperty`, `ForPath`, `ForCtorParam`, `ReverseMap` with unflattening, open generic maps and inline configuration.
- **Modern C# Ready.** Positional records, `init`-only properties, `required` members, and Nullable Reference Types (`#nullable enable`).
- **Customization.** Resolvers (`IPropertyResolver`), type converters (`ITypeConverter`), value converters (`IValueConverter`), conditions (`If`, `PreCondition`), fallbacks (`Fallback`), transforms (`AddTransform`), `BeforeMap` and `AfterMap`, and polymorphic inheritance with `Include`, `IncludeBase`, `IncludeAllDerived`, and `As<T>()`.
- **EF Core projection.** `ProjectOnto<T>()` turns your maps into SQL, with parameters and explicit expansion (`ExplicitExpansion()`).
- **Configuration checks.** `AssertConfigurationIsValid()` and `ValidateConfiguration()` catch unmapped members, type mismatches and missing constructors at startup or in unit tests.
- **Circular reference safety.** `MaxDepth` recursion guards and `PreserveReferences` identity tracking.
- **Performance.** Maps are compiled once into expression trees. A Roslyn source generator writes typed C# code for eligible maps, so they start faster and run under Native AOT. See the [benchmarks against AutoMapper 16.3.0](https://github.com/mrehman29/AutoMapSharp/blob/main/docs/benchmarks/performance-report.md).
- **Compile-time help.** Analyzers warn about unmapped properties (`AMS001`), incompatible types (`AMS002`), and circular references (`AMS003`) as you type. Source generator diagnostic `AMS100` alerts at build time if a map cannot be generated for Native AOT.

## Native AOT & Trimming

Maps emitted by the Roslyn source generator run under Native AOT. CI publishes a native binary and verifies it on every build for `linux-x64`.

- Maps the generator emits need no dynamic code generation and run under Native AOT.
- Generator diagnostic `AMS100` informs you at build time when a map cannot be generated and will require expression trees.
- Maps that are not generated fall back to compiled expression trees and fail under Native AOT with an `AutoMapSharpConfigurationException`.
- Publishing with `<PublishAot>true</PublishAot>` reports trim warnings from the library's reflection fallback engine. They do not affect generated maps. Annotating the fallback is planned.
- Runtime features requiring dynamic compilation are not supported under Native AOT: `ProjectOnto`, `BuildExecutionPlan`, dictionary mapping, and open generic maps.

See the [Native AOT and trimming guide](https://github.com/mrehman29/AutoMapSharp/blob/main/docs/features/native-aot-and-trimming.md).

## Performance Benchmarks

Measured with BenchmarkDotNet 0.14.0 on an Apple M3 Ultra (macOS 26.5.2, .NET 8.0.14, Arm64 RyuJIT) using a `ShortRun` job with 3 iterations. Treat differences under about 10% as noise.

From the Phase 11 compiled engine benchmarks:

| Scenario | AutoMapSharp | AutoMapper 16.3.0 | Comparison |
|---|---|---|---|
| Flat object, 10 properties | 30.2 ns | 46.1 ns | 0.66x of AutoMapper time, faster |
| Nested order with customer, address, 3 lines | 154.2 ns | 112.2 ns | 1.37x slower |
| List of 1,000 flat objects | 25.3 µs | 19.6 µs | 1.29x slower |
| One `MapSource` / `MapFrom` expression | 29.5 ns | 43.6 ns | 0.68x of AutoMapper time, faster |

- **Allocations:** AutoMapSharp allocates 56 bytes more than hand-written code per call for a flat map (the per-call `ResolutionContext`).
- **Cold start:** In a separate console app test timing the first map in a new process, generated code started in about 16.5 ms compared to about 29.5 ms for a compiled plan.

See the full [performance report](https://github.com/mrehman29/AutoMapSharp/blob/main/docs/benchmarks/performance-report.md).

## Moving from AutoMapper

Start with the [migration guide](https://github.com/mrehman29/AutoMapSharp/blob/main/MIGRATION_GUIDE.md). It has a side-by-side table of every API and lists the few behavior differences.

To do most of the rewriting automatically:

```bash
dotnet tool install --global dotnet-automapsharp-migrate
automapsharp-migrate ./src --dry-run
```

Or add `AutoMapSharp.MigrationAnalyzer` to your project and apply its quick fixes in your IDE or via `dotnet format`. The analyzer reports `AMSMIG001`–`AMSMIG008`. Its quick fix and the CLI tool use the same migrator, which also rewrites `Condition` → `If`, `NullSubstitute` → `Fallback`, and `IValueResolver` → `IPropertyResolver` (reported as `AMSMIG009`–`AMSMIG011` in the CLI's change report).

## Known Limitations and Post-GA Roadmap

- `RecognizeAlias` is not planned; use `MapSource`.
- `AutoMapper.Extensions.ExpressionMapping` is not planned.
- In `ProjectOnto`, resolvers, value converters, and custom conditions execute arbitrary .NET code that cannot be translated to SQL; AutoMapper also cannot translate most of them.
