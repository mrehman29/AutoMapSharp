# AutoMapSharp 1.0.0-preview.1

The first public preview of AutoMapSharp: a free, MIT-licensed object mapper for .NET with an API that will feel familiar if you have used AutoMapper.

## Packages

| Package | What it is for |
|---|---|
| [AutoMapSharp](https://www.nuget.org/packages/AutoMapSharp) | The mapping engine, with the source generator and analyzers built in |
| [AutoMapSharp.Extensions.DependencyInjection](https://www.nuget.org/packages/AutoMapSharp.Extensions.DependencyInjection) | `AddAutoMapSharp` for `IServiceCollection` |
| [AutoMapSharp.Collections](https://www.nuget.org/packages/AutoMapSharp.Collections) | Merge collections by key, a replacement for AutoMapper.Collection |
| [AutoMapSharp.MigrationAnalyzer](https://www.nuget.org/packages/AutoMapSharp.MigrationAnalyzer) | IDE quick fixes that rewrite AutoMapper code |
| [dotnet-automapsharp-migrate](https://www.nuget.org/packages/dotnet-automapsharp-migrate) | A .NET tool that migrates a whole folder from AutoMapper |

```bash
dotnet add package AutoMapSharp --prerelease
dotnet add package AutoMapSharp.Extensions.DependencyInjection --prerelease
```

Targets .NET Standard 2.0, .NET 8 and .NET 9.

## Highlights

- **Familiar API.** Mapping modules, `DefineMap`, `ForProperty`, `ForPath`, `ForCtorParam`, `ReverseMap` with unflattening, open generic maps and inline configuration.
- **Customization.** Resolvers, type converters, value converters, conditions, fallbacks, transforms, `BeforeMap` and `AfterMap`, and inheritance with `Include` and `IncludeBase`.
- **EF Core projection.** `ProjectOnto<T>()` turns your maps into SQL, with parameters and explicit expansion.
- **Configuration checks.** `AssertConfigurationIsValid()` catches unmapped members, type mismatches and missing constructors at startup.
- **Performance.** Maps are compiled once. A source generator writes typed code for eligible maps, so they start faster and run under Native AOT. See the [benchmarks against AutoMapper 16.3.0](https://github.com/mrehman29/AutoMapSharp/blob/main/docs/benchmarks/performance-report.md).
- **Compile-time help.** Analyzers warn about unmapped properties, incompatible types and circular references as you type.

## Moving from AutoMapper

Start with the [migration guide](https://github.com/mrehman29/AutoMapSharp/blob/main/MIGRATION_GUIDE.md). It has a side-by-side table of every API and lists the few behavior differences.

To do most of the rewriting automatically:

```bash
dotnet tool install --global dotnet-automapsharp-migrate --prerelease
automapsharp-migrate ./src --dry-run
```

Or add `AutoMapSharp.MigrationAnalyzer` to your project and apply its quick fixes in the IDE.

## Known limitations

- This is a preview. The API may still change before 1.0.0.
- Native AOT works for maps the source generator can produce. Maps that need the reflection-based engine are not supported under AOT yet.
- `IncludeMembers`, `ForAllMaps` and `SetMappingOrder` are not supported yet. The [parity matrix](https://github.com/mrehman29/AutoMapSharp/blob/main/docs/automapper-parity-matrix.md) shows the full picture.
